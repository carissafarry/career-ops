## 3. Their behaviour we now have

- **Run queue** (`1d159dca`): "Score shortlist" no longer starts every role at once. Three evaluate/pdf runs go at a time, the rest show "Queued: k waiting". Change the cap with `localStorage["career-ops:max-parallel-runs"]` (1-20).
- **Inbox age** (`d518fcc6`): a posting's age counts from the local day, never negative. The age on mobile rows can differ by one day from before.
- **Assistant console** (`24cb5cd4`) and `spend_tier` model names for Claude Code (`d149ff6e`).
- **New providers, all opt-in** (nothing runs until `portals.yml` has an entry): `wellfound` (company pages and the filtered board), `goldman`, `viterbit`, `successfactors-classic`, `oracle_host` for branded ORC hosts, and a `proposal` router mode.
- **Scans that open a browser** go through `lib/hardened-chromium.mjs`, which checks every connection and redirect against an egress list.
- **Tracker fixes**: the tracker is created on first merge, rows with no report can change status, a row's location is filled from its report.
- Many small hardening fixes in the provider layer (linear-time tag stripping, `process.exit` removed after requests).

## 4. Our behaviour that must stay

- `job-store.tsx`: the `repairBriefFor` retry, `startRef`, saving `error` runs with `error: lastLabel`, and `company` in the `co-job-done` refresh. Re-check them after any upstream change to that file.
- `inbox.ts` must stay free of runtime imports from `@/` so its tests run under `node --test`. Put anything that needs `@/lib/explore` in `platform-sources.ts`.
- `globals.css` keeps our violet tokens and the larger cursor rules.
- Unchanged by this merge and not touched upstream: scheduled scans (5-minute floor), `/scans` empty-run toggle, Send/Get filters, Remote button, mobile layouts, `uuid()` fallback.
