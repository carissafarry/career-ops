## 3. Their behaviour we now have

- **Cover answers survive a failed run** (#7441): the run page shows them and the form refills.
- **Apply next skips a closed posting** (#7475), and the day comes from the server (`applyDay`).
- **Quoted chips in Explore** (#7424): `"Portland, OR"` is one entry. The URL form is backward
  compatible, so saved filters written before this still load.
- **Scanner**: `--throttle <ms>` accepted, a bare positional argument or an empty `--ats` is refused
  (#7449, #7450); a labelled posting with a new requisition id comes back even when the company is
  already in the tracker (#7138); dotted country tags and trailing workplace suffixes
  ("Engineer - Remote") count as the same role (#7443).
- **Output filenames**: the CLI modes (`pdf`, `latex`, `text`, `cover`) now write
  `{NNN}-{company}-{kind}-{candidate}-{date}` into `output/` (#6667), and cover drafts go to
  `output/diagnostics/`.
- **New tools**: `npm run cv:verify-all` (every pre-send check on one CV, plus a dead-link check),
  `node interview-jd-terms.mjs` (read-only: words that interview-stage JDs share and
  `content_filter.positive` lacks), `pii-workspace.mjs`, `check-output-names.mjs`.
- Provider fixes (Rippling, Personio, Workday `myworkdaysite`), a `velorahr` provider (opt-in),
  tracker pipe matching, `linkedin-import` and tracker delete no longer hang.
