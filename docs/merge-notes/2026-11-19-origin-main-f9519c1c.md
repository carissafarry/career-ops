## 3. Their behaviour we now have

What the user can notice, in the web app:

- **Explore, "already evaluated" mark** (`5c7acaf3`). A posting counts as scored when the
  evaluated report's URL is the same posting (an apply link counts), not only when company
  and title look alike. A tracker row with no URL is matched by exact company and title only.
- **Pipeline table speed** (`1f716210`). Search and tab counts use keys computed once per
  row. No visible change except speed.
- **Scan location filter** (`611b197b`). In `allow` and `always_allow`, the entry `Washington`
  (the state) no longer admits `Washington, DC`. `DC` and `D.C.` match either spelling in
  every tier. `block` and `block_hard` are unchanged. Only matters for US-targeted filters.
- **One dedup key for a Microsoft posting** (`4fccd378`). `/careers/job/{pid}` and
  `/careers?pid={pid}` are the same posting. Only the `apply.careers.microsoft.com` host.
- **SmartRecruiters** (`a67c68e7`). A board past 10,000 postings can be read to the end
  (page cap 100 to 300). Default of 50 pages is unchanged. A very large board scans slower.
- **Next.js 16.4.6** (`f2fa7461`). We were already on it.

Not visible in the web app: Workday and Personio `listingIdentity` (`50f18e21`, `a95b1925`),
the `h1b-sponsor` rename (`7f8bb17d`), test and docs fixes (`0060d0c0`, `87f220cc`,
`09651c66`), the `update-system` message for an unknown main commit (`069fb4c6`).

## 4. Our behaviour that must stay

Places we changed that upstream also touches. Check these first on the next merge.

- **Removed-from-pipeline flow.** `explore-snapshot.mjs` must keep `inPipelineUrls`, and
  `explorer-view.tsx` must keep `&& !removed.has(o.url)`. Without them, a role the user
  took out of the pipeline stays marked "In pipeline" after a refresh.
- **Pipeline table date filter and column widths** in `pipeline-view.tsx`. Upstream keeps
  reshaping this file for speed; the date range has to stay inside `matchesFilters`.
- **Location filters.** Our country buttons and exclude lists widen a country to its cities
  and provinces in `location-geo.mjs` (`expandPlaces`) before the scanner sees them. Upstream's
  `buildLocationFilter` in `scan.mjs` is what reads them; a change there (like `611b197b`)
  can change what our lists match. After this merge, include `Indonesia` and exclude `Jogja`
  still passes `Bandung, West Java`, `Jakarta` and `Denpasar, Bali`, and still refuses
  `Sleman, Yogyakarta Special Region`.
- **The in-page redirect from `127.0.0.1` to `localhost`** (`layout.tsx`, `origin-guard.mjs`,
  `proxy.ts`). Upstream owns the origin guard; keep the one narrow exception.
